Problematique & Contexte

Le defi de la gestion des identites

  • 1 employe = 5 a 10 comptes (AD, LDAP, ERP, Cloud...)
  • Creation manuelle = erreurs + delais
  • Depart employe = comptes orphelins oublies
  • Aucune tracabilite des acces
  • Risques de securite majeurs
30% des violations liees aux comptes orphelins
4h en moyenne pour creer tous les acces d'un employe

Systemes concernes

  • Active Directory / LDAP
  • ERP (Odoo, SAP)
  • Applications metier (bases SQL)
  • Services Cloud (Keycloak, OAuth)
  • Intranet & outils internes
Besoin : Automatiser et centraliser le cycle de vie des identites numeriques

Notre Solution : IAM Gateway

MidPoint (Evolveum) = puissant mais complexe → Notre gateway simplifie l'interface

1. Automatisation

  • Provisionnement automatique multi-systemes
  • Regles dynamiques (Jinja2)
  • Workflows d'approbation multi-niveaux
  • Calcul automatique (login, email, groupes)

2. Centralisation

  • Un seul point d'entree pour tous les systemes
  • Vue temps reel des identites
  • Reconciliation automatique des ecarts
  • 6 connecteurs natifs

3. Conformite

  • Tracabilite complete (audit logs)
  • Recherche semantique IA
  • Assistant IA integre
  • Conformite RGPD
Innovation cle : Rendre l'IAM accessible a tous, pas seulement aux experts MidPoint

Architecture

  • Frontend : React 18 + TypeScript (port 3000)
  • Backend : FastAPI / Python (port 8000)
  • IGA Central : MidPoint 4.4 (port 8080)

Flux de provisionnement

  • 1. L'utilisateur demande via la Gateway
  • 2. La Gateway applique regles + workflows
  • 3. MidPoint orchestre le provisionnement
  • 4. MidPoint provisionne les systemes cibles

Pourquoi MidPoint au centre ?

  • Moteur IGA open source de reference
  • Gere les projections (shadows) vers LDAP, SQL, etc.
  • Reconciliation native entre systemes
  • Gestion des roles et policies centralisee
  • Notre Gateway = interface No-Code pour MidPoint
Gateway = simplification
MidPoint = orchestration & provisionnement

Difficultes Rencontrees

1. Complexite MidPoint

Probleme : API XML complexe, peu documentee

Solution : Abstraction via REST API

2. Transactions distribuees

Probleme : 1 operation = 4 systemes cibles

Solution : Pattern Saga + compensations

3. Securite moteur regles

Probleme : Jinja2 peut executer du code arbitraire

Solution : SandboxedEnvironment

4. Gestion des secrets

Probleme : 20+ variables sensibles

Solution : .env + validation au demarrage

5. Synchronisation temps reel

Probleme : Coherence eventuelle entre systemes

Solution : Cache invalidation + polling

6. Mapping attributs

Probleme : Schemas differents par systeme

Solution : Config mappings par connecteur

7. Couts & latence IA

Probleme : OpenAI API = cout + latence

Solution : Cache + rate limiting

8. Tests d'integration

Probleme : 14 services = complexite

Solution : Mocks + env dedie
